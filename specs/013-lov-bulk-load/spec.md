# Feature Specification: Bulk Load of Lists of Values (Carga Masiva de LOV)

**Feature Branch**: `013-lov-bulk-load`

**Created**: 2026-11-23

**Status**: Approved

**Approved**: 2026-11-23, by the project owner

**Input**: Project owner's requirement of 2026-11-23 (referred to below as *the feature request*):
«Visual: El usuario accede a la sección de Listas de Valores y selecciona "Crear LOV" o "Carga Masiva de
LOV" (vía Excel/CSV).» Owner decisions of 2026-11-23, taken before this spec: one file may create or
update **several** lists with their values (columns Lista, ID, Etiqueta, Equivalencia); Excel and CSV
files are both accepted; the work is a new feature (013). Business references (official `ERF - HUs`
copies): `p360:ERF - HUs/ERF 1.1 Plantillas.docx` §3.1, §3.2.1 and the bulk import paragraph, and
`p360:ERF - HUs/HU_New PIM HEADLESS_Plantillas.docx` HU2.8.

## Context

### What exists today

| Item | In pim-platform | Consequence |
|---|---|---|
| Lists of values | Feature 006: a list has a unique name and a feature 003 system ID; its values are ID + label + optional equivalence, up to 50,000 per list | What a file creates or updates |
| Creating a list | Feature 006: a "Nueva lista" card with a name and a «Crear lista» button | Becomes the «Crear LOV» action |
| Bulk load | Feature 006 FR-011: inside one open list, a CSV file (ID, Etiqueta, Equivalencia) adds or updates that list's values, all or nothing (FR-016), with a CSV template | Kept; this feature adds a load for many lists at once, and Excel |
| Permission | Feature 006 FR-002: administering lists needs the list-administration permission (provisionally `ATTRIBUTE_CREATE`, A-008) | The same permission applies here |
| System IDs | Feature 003: the "lista de valores" object type has an automatic sequence | New lists get their ID there |

### What the sources say (tier 2)

- ERF §3.2.1 «El PIM debe soportar la administración de LOVs masivamente o de manera manual.»
- ERF bulk import paragraph: «Masiva: Módulo de importación para plantillas y atributos desde una hoja
  de cálculo (Excel, CSV) o APIS. Debe incluir un motor de validación previa (Pre-flight check)…»
- ERF §3.1 duplicate validation: an existing ID «utilizará el ID para actualizarlo (siempre y cuando se
  trate del mismo objeto)».
- HU2.8 "Motor de Validación Previa": «El sistema no aplicará los cambios … hasta que todos los errores
  del reporte hayan sido corregidos» (already the rule of feature 006 FR-016).
- The feature request (owner, 2026-11-23; not found in the reference repository): the two actions
  «Crear LOV» and «Carga Masiva de LOV» (vía Excel/CSV) on the lists-of-values section.

### Differences from feature 006

| Topic | Feature 006 | This feature |
|---|---|---|
| Scope of one file | Values of the one list that is open | Values of several lists, named in the file; lists that do not exist are created |
| Formats | CSV | CSV and Excel (.xlsx) |
| Where it starts | Inside a list's detail | A top-level action of the lists-of-values page |
| Template | CSV, columns ID, Etiqueta, Equivalencia | CSV and Excel, columns Lista, ID, Etiqueta, Equivalencia |
| Label of the create action | «Crear lista» in a "Nueva lista" card | «Crear LOV» |

## Clarifications

### Session 2026-11-23

- Q: How does a file row name its list — by name, by list system ID, or either? → A: **By name only**
  (OQ-001, Option A); a name that matches no list creates it (FR-006).
- Q: When the file is valid, is it applied at once or after a summary the user confirms? → A:
  **Summary first, applied on confirmation** (OQ-002, Option B; FR-010).

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Load several lists from one file (Priority: P1)

An authorized user opens the lists-of-values page, chooses «Carga Masiva de LOV», downloads the
template if needed, and uploads one CSV or Excel file whose rows give, for each value, the list it
belongs to, its ID, its label and, optionally, its equivalence. Lists named in the file that do not
exist are created; lists that exist get the new values added and the existing ones updated. Nothing is
saved unless the whole file is valid.

**Why this priority**: This is the feature request: lists are loaded massively instead of one by one.
Without it nothing else in this feature has value.

**Independent Test**: With lists «Color» (values ROJ, AZU) existing and «Talla» not existing, upload a
file with rows for «Color» (AZU relabelled, VER new) and «Talla» (CH, MD); afterwards «Color» has ROJ,
AZU (new label) and VER, and «Talla» exists with CH and MD and a generated system ID.

**Acceptance Scenarios**:

1. **Given** no list named «Talla», **When** a valid file has rows for «Talla», **Then** the list
   «Talla» is created with a system ID generated by feature 003 and the rows as its values, in file
   order.
2. **Given** the list «Color» with value AZU «Azul», **When** a valid file has a «Color» row with ID
   AZU and label «Azul marino», **Then** AZU's label becomes «Azul marino»; its equivalence changes
   only if the row's Equivalencia cell is not empty (feature 006 FR-011).
3. **Given** a valid file, **When** it is uploaded, **Then** the page first shows a summary — lists to
   be created and to be updated and, per list, values to be added and to be updated — and nothing is
   saved yet; **When** the user confirms, **Then** the file is applied and the page reports what was
   created and updated; **When** the user cancels instead, **Then** nothing changes.
4. **Given** a file with an empty ID cell, **When** it is applied, **Then** that value gets a generated
   ID that collides with no other value of its list (feature 006 FR-009).
5. **Given** a list's values that are not in the file, **When** the file is applied, **Then** they are
   kept unchanged.

---

### User Story 2 - See every error before anything is saved (Priority: P1)

The whole file is checked first. When any row is wrong, nothing is saved and the user gets a report
listing every problem with its row number, column and cause in Spanish, so the file can be fixed and
uploaded again.

**Why this priority**: The sources require the pre-flight check (ERF bulk paragraph, HU2.8), and a
half-applied file over several lists would be hard to repair. It ships with User Story 1.

**Independent Test**: Upload a file with one valid row, one row without label and two rows with the
same list and ID; nothing changes in any list and the report names the three problem rows.

**Acceptance Scenarios**:

1. **Given** a file with any invalid row, **When** it is uploaded, **Then** no list is created or
   changed and every invalid row is reported with its row number (as the user sees it in the file),
   its column and the cause.
2. **Given** two rows with the same list and the same value ID (ignoring case, feature 006 A-004),
   **When** the file is uploaded, **Then** both rows are reported as duplicates (feature 006 OQ-005).
3. **Given** a row that would push a list over 50,000 values, **When** the file is uploaded, **Then**
   the file is refused with the list's name and its resulting number of values.
4. **Given** a file that is not CSV or Excel, is empty, has no data rows, or lacks the Lista, ID or
   Etiqueta column, **When** it is uploaded, **Then** it is refused with a message saying what is
   wrong and nothing is saved.
5. **Given** a user without the list-administration permission, **When** they look at the page,
   **Then** neither «Crear LOV» nor «Carga Masiva de LOV» is offered, and a direct request is refused.

---

### User Story 3 - Start from the two actions and a template (Priority: P2)

On the lists-of-values page, the user sees two clear actions: «Crear LOV», which creates one list by
name as today, and «Carga Masiva de LOV», which opens the bulk load with a downloadable template in CSV
and in Excel, and a short explanation of the columns.

**Why this priority**: It is the visible part of the feature request and makes the load
self-explanatory, but loading itself (P1) is the value.

**Independent Test**: Open the page as an authorized user; both actions are there; the downloaded
templates open in a spreadsheet tool with the columns Lista, ID, Etiqueta, Equivalencia and an example
row.

**Acceptance Scenarios**:

1. **Given** the lists-of-values page, **When** an authorized user opens it, **Then** the actions
   «Crear LOV» and «Carga Masiva de LOV» are shown.
2. **Given** «Crear LOV», **When** the user enters a name and confirms, **Then** one list is created
   exactly as with today's «Crear lista» (feature 006 FR-001, FR-003).
3. **Given** «Carga Masiva de LOV», **When** the user chooses a template, **Then** a CSV or an Excel
   file with the four columns and an example row is downloaded.
4. **Given** an open list, **When** the user uses its own «Carga masiva» of values (feature 006
   FR-011), **Then** it works as before.

### Edge Cases

- **List names that differ only in letter case or surrounding spaces** («color», « Color »): they name
  the same list (feature 006 FR-003, A-002), whether it exists or is created by the file.
- **A new list name longer than allowed or blank**: the rows are reported (feature 006 FR-003 rules).
- **The same new list named in many rows**: one list is created; its system ID is generated once.
- **ID cells with leading zeros** (`0001`): kept as text (feature 006 FR-007), also in Excel, where
  such cells are often numbers; a number cell is read as the digits the user sees.
- **An Excel file with several sheets**: only the first sheet is read (A-004).
- **Blank rows**: skipped; they do not count as errors.
- **Equivalencia column missing**: allowed (feature 006 FR-011); no equivalence changes.
- **Two users loading at the same time, or a list deleted while a file is checked**: the file is
  checked again when it is applied; if anything it relied on changed, nothing is saved and the user is
  asked to upload it again.
- **Feature 003 cannot give an ID for a new list** (sequence exhausted): nothing is saved and the
  message of feature 003 is shown.

## Requirements *(mandatory)*

### Functional Requirements

**Page and actions**

- **FR-001 – Two actions**: The lists-of-values page MUST offer, to users with the list-administration
  permission (feature 006 FR-002), the actions **«Crear LOV»** and **«Carga Masiva de LOV»**.
  [feature request]
- **FR-002 – Crear LOV**: «Crear LOV» MUST create one list by name with feature 006's rules (FR-001,
  FR-003); it replaces the «Crear lista» button and the "Nueva lista" card title. [feature request]
  *Amended 2026-11-23 by the project owner («El usuario define el ID de Lista, Nombre de la Lista…»;
  source not found in the reference repository): «Crear LOV» MUST also offer an optional **ID** of the
  list, before the name. Empty means the ID is generated by feature 003's sequence, as before; a typed
  ID follows feature 003's manual-ID rules (permission for the "lista de valores" object type, format,
  unique across the system) and its refusals are shown under the ID field. The backend already accepted
  it (feature 006 FR-001, contract `CreateListOfValuesRequest.systemId`); only the screen changes.*
- **FR-003 – Carga Masiva de LOV**: «Carga Masiva de LOV» MUST let the user upload one CSV or Excel
  (.xlsx) file and MUST offer a downloadable template in both formats. [feature request; ERF bulk
  paragraph «hoja de cálculo (Excel, CSV)»]
- **FR-004 – Per-list load stays**: The value load inside one list (feature 006 FR-011) MUST keep
  working unchanged.

**File content**

- **FR-005 – Columns**: The file MUST have a header row with the columns **Lista**, **ID**,
  **Etiqueta** and, optionally, **Equivalencia**, in any order, matched ignoring letter case, accents
  and surrounding spaces. Each following row is one value of the list named in its Lista cell.
- **FR-006 – Naming a list**: A row MUST name its list **by its name** in the Lista cell (OQ-001,
  Option A); list system IDs are not read from the file. A name matches an existing list ignoring
  letter case and surrounding spaces (feature 006 A-002); a name that matches no existing list creates
  a new list with that name, which MUST follow feature 006 FR-003.
- **FR-007 – Value rules**: Every row MUST follow feature 006's value rules: label required (FR-006),
  ID kept as text (FR-007), an empty ID is generated (FR-009), an existing ID of that list updates the
  value's label, and its equivalence when the Equivalencia cell is not empty (FR-011), and the same
  list and ID twice in one file is an error (OQ-005).
- **FR-008 – New lists**: A new list MUST get its system ID from feature 003's automatic sequence for
  the "lista de valores" object type; the file cannot set it (A-003).
- **FR-009 – Values not in the file**: Values of an existing list that the file does not mention MUST
  be kept unchanged. A file MUST NOT delete values or lists.

**Check and apply**

- **FR-010 – Check first, then confirm**: The whole file MUST be checked before anything is saved
  (OQ-002, Option B). When it is valid, the user MUST first see a **summary** of what will change —
  the lists to be created and to be updated and, per list, the number of values to be added and to be
  updated — and the file MUST be applied only when the user confirms. The user MAY cancel instead;
  then nothing is saved. When it is applied, the file MUST be checked again, and if the data changed
  since the summary in a way that affects it, nothing is saved and the user is asked to load it again.
- **FR-011 – All or nothing**: A file with any invalid row MUST change nothing, in any list (feature
  006 FR-016). A valid file MUST be applied completely: every list it creates or changes, or none.
- **FR-012 – Error report**: Every invalid row MUST be reported with its row number as seen in the
  file, its column and the cause, in Spanish; file-level problems (format, missing column, no rows,
  too large) MUST be reported with what to fix.
- **FR-013 – Result**: After a file is applied, the page MUST show the lists created and updated and,
  per list, the number of values added and updated, and the list overview MUST show the new lists.
- **FR-014 – Limits**: A file MUST NOT exceed 50,000 data rows, and no list may end up with more than
  50,000 values (feature 006); a file over either limit MUST be refused as a whole (A-005).
- **FR-015 – Permission**: Loading a file MUST require the list-administration permission (feature
  006 FR-002, A-008); without it the request MUST be refused and nothing saved.

### Key Entities *(include if feature involves data)*

- **List of values** (feature 006): name, system ID, values. A file may create lists and add or update
  their values; it never deletes them.
- **Value** (feature 006): ID, label, optional equivalence; unique by ID within its list.
- **Bulk load file**: not stored. A CSV or Excel file whose rows are (list, value ID, label,
  equivalence). Its check produces either a report of problems (row, column, cause) or a result
  (lists created/updated, values added/updated per list).

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: A user loads 3 lists with 1,000 values in total from one file, including downloading the
  template, in under 5 minutes.
- **SC-002**: A file of 50,000 rows spread over several lists is checked and applied, or refused with
  its report, in under 30 seconds.
- **SC-003**: For a file with errors, 100% of the invalid rows are reported in one attempt, and no list
  changes.
- **SC-004**: The same file loaded as CSV and as Excel gives exactly the same lists and values.
- **SC-005**: Users find «Crear LOV» and «Carga Masiva de LOV» on the lists-of-values page without
  searching.

## Assumptions

- **A-001**: The list-administration permission of feature 006 applies (provisionally
  `ATTRIBUTE_CREATE`, feature 006 A-008).
- **A-002**: Matching of list names follows feature 006 FR-003 / A-002 (ignore letter case and
  surrounding spaces; accents count: «Tamaño» and «Tamano» are different lists).
- **A-003**: New lists always get a generated system ID; a manual system ID for a new list (feature 003
  permission) is not offered in the file. It can be added later if needed.
- **A-004**: In an Excel file only the first sheet is read; other sheets are ignored. Only .xlsx is
  accepted (not the old .xls format).
- **A-005**: Limits reuse feature 006: 50,000 data rows per file and 50,000 values per list. A file
  size limit is set in the plan.
- **A-006**: The file is not kept after the load; there is no history of loads in this feature.
- **A-007**: Rows are applied in file order, so a new list's values keep the file order.
- **Out of scope**: loading by API; importing templates or attributes; deleting values or lists from a
  file; linking lists to attributes; an audit trail of loads.
